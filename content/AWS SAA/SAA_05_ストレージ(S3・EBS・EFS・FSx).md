## 3種類のストレージ
| 種類 | イメージ | AWS のサービス |
| --- | --- | --- |
| **オブジェクト** | ファイルを丸ごと置く倉庫。URL で取り出す | **S3** |
| **ブロック** | パソコンのディスク。1台のサーバーにつなぐ | **EBS**、インスタンスストア |
| **ファイル** | 共有フォルダ。複数台から同時にマウント | **EFS**(Linux/NFS)、**FSx**(Windows など) |

## S3
- 容量は無制限、1オブジェクト最大 5TB(大きいファイルは**マルチパートアップロード**)
- **耐久性 99.999999999%(イレブンナイン)**。複数 AZ に自動で複製(One Zone 系を除く)
- 書き込み直後から最新を読める(強い整合性)
- バケット名は世界で一意

### ストレージクラス(最頻出)
| クラス | 取り出し | 最低保存期間 | 用途 |
| --- | --- | --- | --- |
| **S3 Standard** | すぐ | なし | よく使うデータ |
| **S3 Intelligent-Tiering** | すぐ | なし | **アクセス頻度が分からない・変わる** → 自動で安い層へ |
| **S3 Standard-IA** | すぐ(取り出し料金あり) | 30日 | たまにしか使わないが、すぐ必要 |
| **S3 One Zone-IA** | すぐ | 30日 | **作り直せる**データ(1つの AZ だけに保存) |
| **S3 Glacier Instant Retrieval** | **ミリ秒** | 90日 | 四半期に1回くらい見るアーカイブ |
| **S3 Glacier Flexible Retrieval** | 数分〜十数時間 | 90日 | バックアップ。迅速 1-5分 / 標準 3-5時間 / 大容量 5-12時間 |
| **S3 Glacier Deep Archive** | 12〜48時間 | 180日 | **一番安い**。法令で7年保存など |

→ 「30日後にほぼ見なくなり、1年後に削除」= **ライフサイクルルール**で Standard → Standard-IA(30日)→ Glacier → 削除。

### 機能
| 機能 | 何ができるか | キーワード |
| --- | --- | --- |
| **バージョニング** | 上書き・削除しても過去の版が残る | 「誤削除からの復旧」 |
| **MFA Delete** | 削除に MFA を必須にする | 「削除をさらに厳重に」 |
| **オブジェクトロック** | 一定期間**消せない・変えられない**(WORM)。コンプライアンスモードはルートでも消せない | 「改ざん防止」「規制で保存義務」 |
| **レプリケーション(CRR / SRR)** | 別リージョン(CRR)/ 同リージョン(SRR)のバケットへ自動コピー。バージョニング必須 | 「DR」「別アカウントにも保存」 |
| **署名付き URL** | 期限付きで、非公開オブジェクトを一時的に見せる/アップロードさせる | 「ログインした人だけダウンロード」 |
| **Transfer Acceleration** | エッジ経由で遠くからのアップロードを高速化 | 「海外から大きなファイルをアップロード」 |
| **イベント通知** | アップロードされたら Lambda・SQS・SNS・EventBridge を起動 | 「画像がアップされたらサムネイル作成」 |
| **静的ウェブサイトホスティング** | HTML をそのまま公開(HTTPS は CloudFront を前に置く) | — |
| **ブロックパブリックアクセス** | うっかり公開を防ぐ(デフォルトで有効) | — |
| **S3 Select / Athena** | S3 上のデータを SQL で検索 | 「S3 のログを SQL で分析」 |

### アクセス制御
- **バケットポリシー**(リソースベース)と **IAM ポリシー**で制御。ACL は基本的に無効化(推奨)
- CloudFront 経由だけにしたい → **OAC**

## EBS(EC2 のディスク)
- **1つの AZ の中**だけ。基本は1台の EC2 にだけつなぐ(io1/io2 は同じ AZ 内で Multi-Attach 可)
- **スナップショット**は S3 に保存され、別 AZ・別リージョンにコピーできる
- 暗号化は KMS。暗号化されていないボリュームは、スナップショットを暗号化コピー → そこから作り直す

| タイプ | 種類 | 特徴 | 用途 |
| --- | --- | --- | --- |
| **gp3** | SSD 汎用 | 3,000 IOPS が標準。**IOPS と容量を別々に決められる** | ほとんどの場合これ |
| **gp2** | SSD 汎用 | 容量に比例して IOPS が増える(旧世代) | — |
| **io2 Block Express / io1** | SSD 高性能 | 非常に高い IOPS を指定できる | 大規模 DB、「IOPS が足りない」 |
| **st1** | HDD スループット | 大きなデータを順番に読む。**起動ディスク不可** | ビッグデータ、ログ処理 |
| **sc1** | HDD コールド | 一番安い。**起動ディスク不可** | めったに使わないデータ |

## EFS と FSx(共有ファイルストレージ)
| サービス | プロトコル | OS | 特徴・キーワード |
| --- | --- | --- | --- |
| **EFS** | NFS | **Linux** | 複数 AZ から**数千台が同時にマウント**。容量は自動で伸び縮み。低頻度アクセスクラスあり |
| **FSx for Windows File Server** | **SMB** | Windows | **Active Directory と連携**、Windows の共有フォルダ |
| **FSx for Lustre** | Lustre | Linux | **HPC・機械学習**の超高速処理。S3 と連携 |
| **FSx for NetApp ONTAP** | NFS / SMB / iSCSI | 両方 | 既存の NetApp からの移行 |
| **FSx for OpenZFS** | NFS | Linux | 既存の ZFS からの移行 |

→ 「複数の Linux EC2 で同じファイルを共有」= **EFS**、「Windows の共有フォルダ」= **FSx for Windows**、「HPC」= **FSx for Lustre**。

## オンプレミスとつなぐ・データを運ぶ
| サービス | 用途 | キーワード |
| --- | --- | --- |
| **Storage Gateway** | オンプレのサーバーから AWS のストレージを使う | |
| ├ ファイルゲートウェイ | NFS/SMB で S3 にファイル保存 | 「オンプレから S3 をファイル共有として」 |
| ├ ボリュームゲートウェイ | iSCSI ディスクを S3 にバックアップ | 「オンプレのディスクのバックアップ」 |
| └ テープゲートウェイ | 物理テープの代わり | 「テープバックアップを置き換え」 |
| **DataSync** | オンプレ ↔ S3/EFS/FSx へ**ネット経由で**自動転送・同期 | 「定期的に大量ファイルを転送」 |
| **Snowball Edge** | **物理デバイスを郵送**してデータ移行 | 「数十 TB 以上」「回線が細い」「数週間かかる」 |
| **Transfer Family** | SFTP/FTPS で S3・EFS に転送 | 「取引先が SFTP でファイルを送ってくる」 |

→ 回線で何日かかるかを計算して、**1週間以上かかるなら Snowball** が目安。
