Skills・サブエージェント・Hooks・MCP サーバー・LSP(言語サーバー)などを**1つにまとめてインストールできるパッケージ**。
- 単体の Skill や MCP は「自分だけ・1プロジェクト」なら十分。**複数リポジトリで同じ構成を使いたい / 人に配りたい**時にプラグインにする
- プラグインの Skill は名前空間付き: `/プラグイン名:スキル名`(他と衝突しない)
- **マーケットプレイス** = プラグインのカタログ。Anthropic 公式(`claude-plugins-official`)が最初から入っている

## 使う(インストール)
```text
/plugin                                              # Discover タブで探す
/plugin install commit-commands@claude-plugins-official   # 詳細画面を開き、スコープを選んで導入
```
- 詳細画面で「何が入るか」「コンテキストコスト(毎ターン/呼び出し時)」を確認できる
- **プラグインは Hook や MCP を実行できる**ので、入れる前に中身を確認
- 反映されない時は `/reload-plugins`
- シェルから: `claude plugin install ...` `claude plugin list`
- マーケットプレイスの追加とインストールを一度に: `claude plugin install <plugin> --marketplace <source>`
- 設定値のあるプラグイン: `claude plugin configure <plugin>`
- 入れる前に中身を確認: `claude plugin validate ./plugin-dir`(Mod が扱うイベントや呼ぶ API も一覧表示)
- npm から入れるプラグインは install スクリプトを実行しない(`--ignore-scripts`)
- claude.ai アカウントで有効にしたプラグインはターミナルにも同期される(止めるなら `syncClaudeAiPlugins: false`)

### インストールスコープ
| スコープ | 有効範囲 |
| --- | --- |
| user | 自分の全プロジェクト(ターミナル・デスクトップ・VS Code 共通) |
| project | リポジトリの `.claude/settings.json` 経由でチーム全員(各自のPCでインストールは必要) |
| local | 自分・このリポジトリだけ |
※ クラウドセッションはローカル設定のプラグインを読まない

### マーケットプレイスを追加
```text
/plugin marketplace add owner/repo          # GitHub
/plugin marketplace add https://.../marketplace.json
/plugin marketplace add ./path/to/dir
```

## おすすめの公式プラグインの種類
- **コードインテリジェンス(LSP)**: TypeScript、Python など言語ごと。編集直後に型エラーを検知、定義・参照をシンボルで検索 → grep で大量に読むより正確で省コンテキスト(言語サーバー本体のインストールも必要。クラウドでは動かない)
- **security-guidance**: Claude が書いたコードを自動で自己セキュリティレビュー
- **Claude Security**: コードベース全体の脆弱性スキャン
- **commit-commands** などのワークフロー系
- **Channels**(Telegram / Discord / iMessage): 外部からセッションにメッセージを送る

## 作る
構成:
```text
my-plugin/
├── .claude-plugin/
│   └── plugin.json      # マニフェスト(名前・説明・バージョン)。ここには plugin.json だけ置く
├── skills/<name>/SKILL.md
├── agents/xxx.md
├── hooks/hooks.json
└── .mcp.json
```
- 開発中は `claude --plugin-dir ./my-plugin` でインストールせずに読み込んで試す
- `claude plugin eval` でテストケースを回し、プラグインなしと比較して効果を採点できる
- 配布: GitHub などに `marketplace.json` を置いてマーケットプレイスとして公開
- 既存の Skill フォルダに `.claude-plugin/plugin.json` を足すだけでプラグイン化もできる

## Mods(モッド、v2.1.287〜)
プラグインの一種で、**JavaScript / TypeScript のイベントハンドラ(hook と呼ぶ)が Claude Code の中で動き**、画面や動作を変える。

できること:
- 自分用の UI を描く(会話の横のペイン、入力欄の上の帯、タブ・ボタン・入力欄)
- Claude Code 自身の表示を描き変える(ツール呼び出しの行、スピナー、質問ダイアログなど)。※権限確認ダイアログだけは変えられない
- ツール呼び出しやリクエストに割り込む(実行前に質問する、書き換える、別のモデルに送る)
- Claude のターンなしで即座に動く `/コマンド` を作る

```text
first-mod/
├── .claude-plugin/plugin.json
└── hooks/
    ├── hooks.json     # register.js を指す
    └── register.js    # export function register(on) { on('tool.call', ...) }
```
- **作り方**: セッションで「〜する Mod を作って」と頼めば Claude が書く(組み込みの `plugin-authoring` スキル)。サンプルは GitHub の `anthropics/claude-code-playground` の `claude-code/mods`
- **入れ方**: 普通のプラグインと同じ(`/plugin install 名前@マーケットプレイス`)。試すだけなら `--plugin-dir`
- **組み込み Mod**: `/diff` のパネル、AGENTS.md の読み込み、「You should know」(見落としを入力欄の上に知らせる。`/plugin enable cc-plugin-you-should-know@builtin` で ON)など。`/plugin` → Installed → Built-in で確認
- **止める**: 1つなら `/plugin` で無効化、そのセッションだけ全部なら `--safe-mode`、常に全部なら `"disableAllHooks": true`
- 動く場所: ターミナル・デスクトップの Code タブ・VS Code。`claude -p` や SDK、クラウドでは hook は動くが描画はされない

> **注意**: Mod はサンドボックスの外で**あなたの権限で動くコード**。ファイル・環境変数(APIキー)・すべてのプロンプトとツール呼び出しにアクセスでき、確認なしにツールを承認することもできる。信頼できる作者のものだけ入れ、入れる前に `claude plugin validate` で中身を確認する。

## 組織向け
- 管理設定で許可するマーケットプレイス・プラグインを制限できる
- 組織におすすめプラグインを提示する仕組みもある
- Mod も管理設定で制限できる(`allowManagedModsOnly` など)
