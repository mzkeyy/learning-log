## UI と UX
| | UI(User Interface) | UX(User Experience) |
| --- | --- | --- |
| 対象 | 画面・ボタン・文字・色・操作 | サービスを知る前〜使った後までの**体験全体**と感情 |
| 問い | 見やすいか、操作しやすいか | 目的を達成できたか、どう感じたか、また使いたいか |
| 例 | ボタンの色・配置 | 「迷わず予約できて安心した」「楽しかった」 |
UI は UX の一部。良い UI でも、目的に合っていなければ良い UX にはならない。

## UX を考える枠組み(実務で使う)
### 1. 誰の・どんな状況の・どんな目的か
- ペルソナ(代表的な利用者像)、利用シーン(スマホで移動中?PCで落ち着いて?)
- 任天堂の例: プレイヤーだけでなく**横で見ている家族**、**保護者と子ども**も対象にしている

### 2. 体験の流れ(カスタマージャーニー)
```
知る → 興味を持つ → 初めて使う → 使い続ける → 人に勧める / やめる
```
- 各段階で「行動・考え・感情・不満」を書き出す
- **初めて使う瞬間**(ファーストインプレッション)は特に重要([[UXデザイン_02_伝え方とあそび心(マリオメーカー等の事例)]])

### 3. 使いやすさの基本(ユーザビリティ)
- 分かりやすい(説明なしで使える)
- 迷わない(次に何をすればいいか分かる)
- 失敗しにくい・失敗から戻れる(確認、取り消し)
- 状態が分かる(読み込み中、完了、エラー)
- 一貫している([[デザインの4原則|反復]])

### 4. 感情
- 不安・ストレスを減らす(分かりやすさ)
- 喜び・驚きを足す(新鮮さ・遊び心)
- 任天堂の3事例は、この2つを両立させる方法を示している

## UX を確かめる方法
- **ユーザーになってみる**: 自分で・家族で実際に使う
- ユーザーテスト(5人程度でも問題の多くが見つかる)
- 行動の可視化・分析(どこで離脱したか)
- 早い段階で方向性を共有して意見をもらう
