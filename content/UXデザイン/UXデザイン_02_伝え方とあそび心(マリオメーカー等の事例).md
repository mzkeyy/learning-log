## 伝え方の3つの心がけ
### 1. 教えることより、体験してもらうこと
- 長い説明を読ませるより、**触ってもらう**ほうが伝わる
- 作り手自身が**ユーザーになってみる**ことが出発点
- 情報は「多すぎ」も「少なすぎ」も悪い UI(講演では UI クイズで、問題・回答・正解の伝え方の違いを示した)

### 2. はじめての体験は貴重
- 最初の印象(ファーストインプレッション)で、その後の関心が決まる
- 最初の数分・最初の1操作を最も丁寧に作る

### 3. 体験はやっぱりおもしろく
- 感情が動くと、次の行動に繋がる

## 事例: スーパーマリオメーカー(Wii U)
- 高機能なのに分かりやすい、を両立
- **触っているうちに機能が発見される**構造(ハテナブロックの例)→「こんなこともできるんだ!」という驚きに変える
- テレビに大きな「手」を表示 → **プレイしていない家族や友達も**何が起きているか分かり、一緒に楽しめる

## あそび心を伝える UI のポイント
1. **「UI 脳」と「娯楽脳」の二人三脚**: 分かりやすさを考える頭と、楽しさを考える頭を両方使う
2. **弱点を遊びのフィルターで強みに変える**: 面倒・つまらない操作も、発想の転換で娯楽にできる
3. **見ている人の席も用意する**(将棋や麻雀の見物席のように): 操作する人以外も楽しめる価値

## Web 制作への翻訳
| 任天堂の考え方 | Web での実践 |
| --- | --- |
| 体験してもらう | 説明文より、触れば分かる UI。デモ・サンプルデータ・プレビューを先に見せる |
| 機能が徐々に発見される | 最初は基本機能だけ見せ、慣れたら応用を案内(プログレッシブ・ディスクロージャー) |
| 初回体験が大事 | 初回登録・空の状態(Empty state)・最初の成功体験を丁寧に。登録前に価値を体験させる |
| 面倒を楽しさに | 待ち時間のアニメーション、完了時の小さな演出、エラー文言をやさしく |
| 見ている人の席 | 共有されたページを受け取った人の体験、画面共有・プレゼン時の見え方 |
