## 全体像
```
原則・ガイドライン(なぜ・どう使うか)            ← デザインシステム / UXデザイン
   │
デザイントークン(色・余白・文字・角丸・影)        ← デザイントークン
   │
プリミティブ(振る舞い: Radix / Base UI / React Aria) ← アクセシビリティ・キーボード操作
   │
共通コンポーネント(Button・Input・Dialog・Card)   ← components/ui(shadcn-ui など)
   │
パターン・複合部品(検索フォーム・データ表・空の状態)
   │
機能のコンポーネント(注文一覧・プロフィール編集)   ← features/
   │
画面(ページ・レイアウト)                          ← app/ や routes/
```

## 押さえどころ
- コンポーネントは「**見た目の部品**」であり「**再利用の単位**」であり「**チームの共通言語**」
- **Atomic Design は考え方の道具**。5段階のフォルダに厳密に分けると、どこに置くか迷う時間が増える。「小さい部品から大きい部品を組み立てる」という発想だけ取り入れるのが今の主流
- 分け方の軸は2つ: **共通(どの機能でも使う)か、機能専用か**、と**見た目だけか、データ・業務を知っているか**
- 複雑な振る舞い(モーダル・メニュー・コンボボックス)は**自作せず、アクセシビリティ対応済みのプリミティブ**を土台にする
- props は少なく、**合成(children)**で柔軟にする。boolean の props を増やし続けない
- 共通部品は **Storybook** でカタログ化し、見た目の変化をテストで検知する
- AI に UI を書かせるときは、**部品の一覧と使い方のルール**を渡す
