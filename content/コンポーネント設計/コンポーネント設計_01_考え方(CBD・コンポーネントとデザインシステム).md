## コンポーネントとは
**見た目と振る舞いをひとまとまりにした、組み合わせて使える UI の部品**。
- 入力(props)を受け取り、画面の一部を返す
- 内側の実装は隠し、決まった使い方(API)だけを公開する(カプセル化 → [[ソフトウェア設計_01_オブジェクト指向(カプセル化・ポリモーフィズム・合成)]])
- 小さな部品を組み合わせて、大きな部品・画面を作る

## CBD(コンポーネント駆動開発)
**画面全体からではなく、部品から作り始め、組み立てて画面にする**開発の進め方。Component-Driven Development / Component-Based Development とも。
```
1. 部品を1つずつ作る(ボタン・入力欄・カード)        ← 単独で表示・確認できる
2. 組み合わせて大きな部品にする(検索フォーム・商品カード)
3. 画面に組み立てる(商品一覧ページ)
4. データとつなぐ
```
| うれしいこと | 説明 |
| --- | --- |
| **単独で作って確かめられる** | アプリ全体を動かさなくても、Storybook などで部品だけ表示・確認できる |
| 状態ごとに確認できる | 読み込み中・空・エラー・長い文字・権限なし…を全部並べて見られる |
| 再利用 | 一度作れば別の画面でも使える。見た目と動きが揃う |
| 分担 | デザイナーと開発者が部品の単位で会話・分担できる |
| テスト | 部品ごとにテストできる → [[テスト_04_コンポーネントテスト(Testing Library・Browser Mode)]] |
- 「画面から作る」と、画面ごとに似た部品が少しずつ違う形で増えていく(ボタンが10種類…)
- 逆に**全部を部品から作ろうとすると遅い**。よく使うものから部品にして、1回しか出てこないものは画面の中にそのまま書いてよい

## デザインシステムとの関係
| | デザインシステム | コンポーネントライブラリ |
| --- | --- | --- |
| 中身 | **原則・ガイドライン・トークン・部品・使い方・ブランド** | 部品のコード |
| 対象 | デザイナー・開発者・PM・AI | 主に開発者 |
| 例 | Material Design、Apple HIG、デジタル庁デザインシステム | MUI、shadcn/ui、Chakra UI |
- コンポーネントライブラリは**デザインシステムの一部**。「なぜこの部品をこう使うか」まで揃ってデザインシステム → [[デザインシステム]]
- 自分のプロダクトでは、既存のライブラリ(shadcn/ui など)を土台に、**自分たちのトークン・ルールを乗せる**のが現実的 → [[shadcn-ui]]

## 良いコンポーネントの条件
| 条件 | 意味 |
| --- | --- |
| **1つの役割** | 「何をする部品か」を一言で言える |
| **予測できる** | 名前と props から、何が表示され、どう動くかわかる |
| **組み合わせやすい** | 他の部品の中に入れても、外に余計な影響を与えない(外側の余白を持たない、など) |
| **状態が揃っている** | 通常・hover・focus・disabled・loading・error・空 |
| **アクセシブル** | キーボードで操作でき、スクリーンリーダーで意味が伝わる → [[Webパフォーマンスとアクセシビリティ_04_アクセシビリティの実装とチェック]] |
| **トークンを使う** | 色・余白を直接書かず、デザイントークンを参照 → [[デザイントークン]] |
| **文書化されている** | 使い方・使ってはいけない場面・例 |

### 外側の余白を持たせない
```tsx
// ❌ ボタン自身が margin を持つと、置く場所ごとに打ち消しが必要
<button className="mt-4 ...">保存</button>

// ✅ 余白は並べる側(レイアウト)が決める
<div className="flex flex-col gap-4">
  <Input />
  <Button>保存</Button>
</div>
```
- 部品は**自分の内側**だけを決め、**外側の配置**は親に任せる

## 考える順番(React の公式の進め方)
1. 画面のデザインを**部品の箱で区切る**(1つの箱 = 1つの役割)
2. まず**静的な版**を作る(データを props で渡すだけ)
3. **最小限の state** を見つける(計算できるものは state にしない)
4. state を**どこに置くか**決める(使う部品の一番近い共通の親)
5. 子から親へのデータの流れ(イベント)をつなぐ
