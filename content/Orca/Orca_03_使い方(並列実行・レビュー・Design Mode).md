## 基本の流れ
```
リポジトリ追加 → ワークツリー作成(1タスク1つ)→ エージェント起動・指示
   → 並列で進行(通知で入力待ちを把握)→ 差分レビュー・コメントで差し戻し
   → コミット・push・PR・CI 確認 → マージ → ワークツリー削除/アーカイブ
```

## 1. リポジトリを追加して3体並べる
1. 左の一覧で **Add Repo** → 手元のリポジトリを選択
2. リポジトリ名の横の **+** → 作業名を入力(空なら自動命名)
3. 起動画面でエージェントと**起点のブランチ**を選ぶ(起点はベース ref・ローカルブランチ・コミット・リモートブランチから選べる)
4. 2〜3 をあと2回繰り返す
5. タブをドラッグして画面分割 → 3体のログを同時に見る
- GitHub の Issue/PR、Linear・Jira の課題からワークツリーを作ると、課題と紐づく(ブランチ名もそちらに合わせる)
- ワークツリー作成は裏で進み、サイドバーに進捗が出る

## 2. 並列の使い分け
| パターン | やり方 | 向いている場面 |
| --- | --- | --- |
| **別タスクを並行** | ワークツリーごとに違う課題 | 機能追加とバグ修正を同時に |
| **同じ課題を競わせる** | 同じ指示を Claude Code・Codex などに | 設計案・UI 案を比較したい |
| **作る役とレビュー役** | A で実装、B(別エージェント)でレビュー | 書いた本人のバイアスを避ける([[07_ベストプラクティス]] の Writer/Reviewer) |
- 並べすぎない: **自分がレビューできる数まで**(2〜3体から)

## 3. 差分をレビューして仕上げる
- 差分ビューで起点との差を確認
- **行ごとにコメント(AI Diff アノテーション)**を付けてエージェントに送り返す
- コミット → push → PR 作成 → CI の結果待ちまでアプリ内で完結
- 削除時に未マージのコミットがあれば、Orca はブランチを残して確認させてくれる
- 使い終わったワークツリーは右クリックでアーカイブ/削除、「Resource Manager → Clean up workspaces」で一括整理

## 4. Design Mode(画面を指さして直させる)
Web 制作で特に便利。
1. 内蔵ブラウザのツールバーで **Design Mode** をオン(カーソルがピッカーに)
2. 直したい UI 要素をクリック → エージェントのチャットに自動で送られる
3. 「ここの余白を広げて」などと指示 → エージェントがコードを直し、Orca が自動リロード
送られる情報: 要素と周辺の HTML、計算済み CSS(色・フォント・余白)、切り抜きスクリーンショット、ソースマップがあればファイル名と行番号。
- 複数の注釈をページに付けてからまとめて送ることもできる
- [[デザインの4原則]] で気づいた点(「ここは近接が崩れている」)を、要素を指して伝えられる

## 5. 便利な操作
- **Quick Open**: ワークツリー・ファイル・コマンドを横断検索
- ファイルや画像をエディタにドラッグ → エージェントへのプロンプトに添付
- Markdown・画像・PDF のプレビュー
- 使用量表示で、どのアカウントがどれだけ使ったか確認

## AI への指示のコツ(Orca で並列にする時)
- タスクごとに**範囲を狭く**(1ワークツリー1目的)。同じファイルを複数タスクで触らない
- それぞれのワークツリーでも CLAUDE.md / AGENTS.md が読まれる → ルールは両方に効くよう AGENTS.md を正本に([[Codex_03_AGENTS.mdとconfig.toml]])
- 完了条件(テスト・型チェック・スクショ確認)を指示に入れておくと、戻ってきた時の確認が楽
