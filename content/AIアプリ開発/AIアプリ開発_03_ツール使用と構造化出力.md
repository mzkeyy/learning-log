## ツール使用(Function Calling)の流れ
LLM は自分で関数を実行できない。**「この関数をこの引数で呼んでほしい」と頼むだけ**で、実行するのはアプリ。
```
1. アプリ → API:  質問 + 使えるツールの一覧(名前・説明・引数の JSON スキーマ)
2. API → アプリ:  stop_reason: "tool_use"、tool_use ブロック { name, input, id }
3. アプリ:        自分のコードで関数を実行(DB 検索・外部 API など)
4. アプリ → API:  これまでの履歴 + tool_result { tool_use_id, content }
5. 2〜4 を繰り返し、stop_reason: "end_turn" になったら答えが完成
```
- この仕組みを共通の規格にしたのが [[MCP]]
- **ツールの説明文**がとても大事。「いつ使うか・何を返すか」を具体的に書く(モデルはそれを読んで選ぶ)

## Tool Runner で書く(おすすめ)
SDK がループ(2〜4)を回してくれる。Zod で引数の型を書くと、検証もしてくれる。
```ts
import Anthropic from '@anthropic-ai/sdk'
import { betaZodTool } from '@anthropic-ai/sdk/helpers/beta/zod'
import { z } from 'zod'

const client = new Anthropic()

const searchOrders = betaZodTool({
  name: 'search_orders',
  description: '顧客の注文を検索する。注文番号か顧客のメールアドレスで探す。最大10件を返す。',
  inputSchema: z.object({
    email: z.string().email().optional(),
    orderId: z.string().optional(),
  }),
  run: async ({ email, orderId }) => {
    const rows = await db.findOrders({ email, orderId })   // 自分の DB
    return JSON.stringify(rows)
  },
})

const final = await client.beta.messages.toolRunner({
  model: 'claude-opus-5-5',
  max_tokens: 16000,
  tools: [searchOrders],
  messages: [{ role: 'user', content: 'taro@example.com の最新の注文はいつ届きますか?' }],
})
console.log(final.content)
```
- Tool Runner は**ベータ**(`client.beta.messages`)
- Zod を使わないなら `betaTool()` に JSON Schema を渡す(その場合は `run` の中で自分で検証する)
- 人の承認が必要な操作(削除・送金・メール送信)は、`run` の中で承認を確認してから実行する

## ループを自分で書く(仕組みの理解用)
```ts
const tools: Anthropic.Tool[] = [{
  name: 'get_weather',
  description: '指定した都市の現在の天気を返す',
  input_schema: {
    type: 'object',
    properties: { city: { type: 'string', description: '都市名(例: 東京)' } },
    required: ['city'],
  },
}]

let messages: Anthropic.MessageParam[] = [{ role: 'user', content: '東京と大阪の天気は?' }]

while (true) {
  const res = await client.messages.create({ model: 'claude-opus-5-5', max_tokens: 16000, tools, messages })
  if (res.stop_reason !== 'tool_use') break               // end_turn など → 完成

  messages.push({ role: 'assistant', content: res.content }) // ★ content を丸ごと戻す

  const results: Anthropic.ToolResultBlockParam[] = []
  for (const block of res.content) {
    if (block.type !== 'tool_use') continue
    try {
      const output = await runTool(block.name, block.input)
      results.push({ type: 'tool_result', tool_use_id: block.id, content: output })
    } catch (e) {
      results.push({ type: 'tool_result', tool_use_id: block.id, content: String(e), is_error: true })
    }
  }
  messages.push({ role: 'user', content: results })        // ★ 結果は1つのメッセージにまとめる
}
```
- **1回の応答で複数のツールを同時に頼まれる**ことがある(並列)。結果は**全部まとめて1つの user メッセージ**で返す
- 失敗したツールも黙って捨てない。`is_error: true` で返すと、モデルが別の方法を考える
- 無限ループ防止に**回数の上限**を付ける
- `tool_use` の `input` は `JSON.parse` 済みのオブジェクトとして扱う。文字列のまま比べない

## ツール選択の指定
| `tool_choice` | 意味 |
| --- | --- |
| `auto`(既定) | 使うかどうかをモデルが決める |
| `none` | ツールを使わせない |
| `any` / `tool`(強制) | 最新モデル(Opus 5.5・Sonnet 5.5・Fable 5.1)では**使えない**(400) |
- 必ず特定のツールを使わせたいときは、`auto` + 指示文で頼み、`strict: true` で引数の形を保証する。**JSON が欲しいだけなら構造化出力を使う**

## Anthropic が用意しているツール(サーバー側で実行)
| ツール | `type` | できること |
| --- | --- | --- |
| Web 検索 | `web_search_20260209` | 最新情報を検索して引用付きで答える |
| Web 取得 | `web_fetch_20260209` | 会話に出てきた URL のページを読む |
| コード実行 | `code_execution_20260521` | サンドボックスで Python・bash を実行(計算・グラフ・ファイル生成) |
| メモリ | `memory_20250818` | 会話をまたいで覚えておく(保存先はアプリが実装) |
| ツール検索 | `tool_search_tool_bm25_20251119` など | ツールが多いとき、必要なものだけ探して読み込む |
```ts
tools: [{ type: 'web_search_20260209', name: 'web_search', max_uses: 5 }]
```
- 実行も結果の組み込みも API 側で行われるので、ループを書かなくてよい
- エラーは例外ではなく**結果ブロックの中**に入って返る(`error_code`)
- 外部の MCP サーバーを API から直接つなぐ **MCP コネクタ**もある(ベータ)

## 構造化出力(JSON で受け取る)
「文章から情報を抜き出して DB に入れる」ような処理は、**決めたスキーマどおりの JSON** で返させる。
```ts
import { z } from 'zod'
import { zodOutputFormat } from '@anthropic-ai/sdk/helpers/zod'

const Inquiry = z.object({
  category: z.enum(['bug', 'billing', 'feature_request', 'other']),
  urgency: z.enum(['low', 'medium', 'high']),
  summary: z.string(),
  customerEmail: z.string().nullable(),
})

const res = await client.messages.parse({
  model: 'claude-opus-5-5',
  max_tokens: 16000,
  messages: [{ role: 'user', content: `次の問い合わせを分類して:\n${inquiryText}` }],
  output_config: { format: zodOutputFormat(Inquiry) },
})

const data = res.parsed_output   // 型付き。失敗すると null
if (!data) throw new Error('解析に失敗')
await db.insertInquiry(data)
```
- `output_config.format` で**スキーマに合う出力を保証**する(古い `output_format` は非推奨)
- 「JSON で答えて」とプロンプトで頼んで正規表現で切り出す方法は、**壊れた JSON が返る**ことがあるので使わない
- 昔のモデルで使われた「assistant の書き出しを先に入れる(prefill)」は、現行モデルでは使えない
- 引用(citations)とは同時に使えない

### strict なツール
```ts
{
  name: 'book_meeting',
  description: '会議を予約する',
  strict: true,   // ★ input がスキーマどおりであることを保証
  input_schema: {
    type: 'object',
    properties: { date: { type: 'string', format: 'date' }, attendees: { type: 'integer' } },
    required: ['date', 'attendees'],
    additionalProperties: false,   // strict に必須
  },
}
```

## 使い分け
| やりたいこと | 使うもの |
| --- | --- |
| 文章から決まった形のデータを取り出す | **構造化出力** |
| 答えるために外の情報や操作が必要 | **ツール使用** |
| 最新情報を調べさせたい | Web 検索ツール |
| 計算・データ分析・ファイル作成 | コード実行ツール |
| 同じツールを複数の AI アプリで使い回したい | **MCP サーバー**にする → [[MCP]] |

## 安全のために
- ツールに渡す権限は**最小限**に(読み取りだけで済むなら書き込みを渡さない)
- ツールの結果に含まれる文章は**データ**。そこに「これまでの指示を無視して…」と書かれていても従わせない設計にする → [[AIアプリ開発_07_評価・コスト・セキュリティ・運用]]
- モデルが作った引数を SQL や シェルにそのまま入れない(プレースホルダを使う → [[Webセキュリティ対策]])
- 取り消せない操作は**人の確認を挟む**
