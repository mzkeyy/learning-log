## エージェントとは
**ツールを使いながら、次に何をするかをモデル自身が決めて、ゴールまで繰り返す仕組み**。中身は [[AIアプリ開発_03_ツール使用と構造化出力]] のループそのもの。
```
目標 ─▶ [モデル: 考える → ツールを選ぶ] ─▶ [アプリ: ツールを実行] ─▶ 結果を返す ─┐
          ▲                                                                        │
          └──────────────────── 終わるまで繰り返す ◀─────────────────────────────┘
```
- [[Claude Code]] や [[Codex]] は、このループに「ファイル操作・コマンド実行・権限管理」を載せた完成品

## 作る前に: 本当にエージェントが必要か
4つすべてに「はい」なら検討する。1つでも「いいえ」なら、単発の呼び出しかワークフローで作る。
| 観点 | 問い |
| --- | --- |
| 複雑さ | 手順を前もって決めきれない、何段階もの作業か |
| 価値 | 遅さ・コストの増加に見合う成果か |
| 実現性 | そのタスクを Claude がうまくこなせるか |
| 失敗の扱い | 間違いを検出して戻せるか(テスト・レビュー・取り消し) |

### ワークフローの型(エージェントより先に考える)
| 型 | 内容 | 例 |
| --- | --- | --- |
| 連鎖 | 前の出力を次の入力に | 抜き出し → 翻訳 → 校正 |
| 振り分け | 最初に分類して、種類ごとに別の処理へ | 問い合わせを請求・技術・その他に |
| 並列 | 同じ入力を複数の観点で同時に処理して集約 | セキュリティ・性能・可読性のレビュー |
| 指揮役と作業役 | 1つが計画し、複数に分担させる | 大きな調査の分担 |
| 評価と改善 | 作る役と評価する役を往復 | 基準を満たすまで書き直す |

## 4つの作り方
| # | 方法 | 自分で書くもの | ループ / 実行環境 | 向く場面 |
| --- | --- | --- | --- | --- |
| 1 | **API + 自前ループ** | ループ全部 | 自分 / 自分 | 仕組みを全部握りたい(→ 03) |
| 2 | **API + Tool Runner** | ツールの関数だけ | SDK / 自分 | 自作ツールのエージェント(**多くの場合これ**) |
| 3 | **Managed Agents** | エージェントの設定 + 自作ツールの結果 | Anthropic / Anthropic | 長時間動く、定期実行、作業用のサンドボックスが欲しい |
| 4 | **Claude Agent SDK** | プロンプトとオプション | SDK(Claude Code そのもの)/ 自分 | ファイル操作・コマンド実行をするエージェント |
- Tool Runner(2)と Agent SDK(4)は名前が似ているが別物。**Tool Runner は自分のツールしか持たない**、Agent SDK は Claude Code の道具(Read・Edit・Bash・Grep・WebSearch など)が最初から入っている
- ループも実行環境(サーバー)も用意してくれるのは **Managed Agents だけ**

### Claude Agent SDK
```ts
import { query } from '@anthropic-ai/claude-agent-sdk'

for await (const message of query({
  prompt: 'src/ のテストが落ちている原因を調べて直して',
  options: {
    allowedTools: ['Read', 'Grep', 'Glob', 'Edit', 'Bash'],
    permissionMode: 'acceptEdits',
    maxTurns: 30,
  },
})) {
  if (message.type === 'result') console.log(message.subtype, message.total_cost_usd)
}
```
- 自分のアプリやバッチ処理に「Claude Code と同じことをするエージェント」を組み込める
- 自作ツール(`tool()` + `createSdkMcpServer()`)、MCP、サブエージェント、Hooks、Skills も使える
- 詳しくは → [[18_管理者向け・Agent SDK・その他]]

### Managed Agents(ベータ)
- **Agent(設定)を1回作り、Session(実行)を何度も始める**
  - Agent: モデル・システムプロンプト・ツール・MCP・Skills をまとめたもの。バージョン管理される
  - Session: 実行ごとに**専用のコンテナ**(作業場所)が用意され、bash・ファイル操作・コード実行がそこで動く
  - 進み具合は**イベントのストリーム**(SSE)で受け取る。ユーザーの発言や自作ツールの結果を送り返す
- 秘密情報は **Vault** に入れると、サンドボックスの中から見えない形で外部 API に渡される
- 定期実行(毎晩のレポートなど)・「基準を満たすまで続ける」(outcomes)・複数エージェントでの分担もできる
- Agent の設定はファイルにしてバージョン管理し、`ant apply` で反映するのが推奨の流れ

## 設計のコツ(公式の考え方)
- **ツールは少なく、よく書く**。似たツールを並べるとモデルが迷う。説明文に「いつ使うか・使わないか」を書く
- ツールが多すぎるなら**ツール検索**(必要なものだけ読み込む)を使う
- 長い作業では**コンテキストが膨らむ**: 古いツール結果を消す(context editing)、要約する(compaction)、ファイルやメモリに書き出す
- 読み込み量の多い下調べは**サブエージェント**(安いモデル)に任せ、結果の要約だけ受け取る
- **予算**(ターン数・トークン・金額)の上限を必ず付ける
- 取り消せない操作は**人の承認**を挟む(Agent SDK の権限設定、Managed Agents の permission policy)
- ログを残し、あとで「なぜそう動いたか」を追えるようにする(→ [[オブザーバビリティ]])

## よくある失敗
- 本当は決まった手順なのにエージェントにして、**遅く・高く・不安定**になる
- 終了条件がなく、同じツールを延々と呼ぶ
- ツールの結果(Web ページ・メール)に書かれた指示に従ってしまう(プロンプトインジェクション → 07)
- 何でもできる強い権限(本番 DB の書き込み・任意コマンド)をそのまま渡す
