## LLM は何をしているか
- 入力された文章の続きを、**トークン**(言葉のかけら)単位で1つずつ予測して出力している
- 自分で Web を見たり DB を読んだりはできない。外の情報が要るときは、**アプリ側が渡す**(RAG)か、**ツールを呼ばせてアプリが実行する**(ツール使用)
- 同じ入力でも毎回少し違う答えになることがある(確率的)。**テストは「完全一致」ではなく評価で見る** → [[AIアプリ開発_07_評価・コスト・セキュリティ・運用]]

## 用語
| 用語 | 意味 |
| --- | --- |
| **トークン** | 料金と長さの単位。英語はおよそ1単語 ≒ 1〜2トークン、日本語は1文字 ≒ 1トークン前後(モデルで違う) |
| **コンテキストウィンドウ** | 1回のリクエストで扱える長さ(入力 + 出力)。現行の Claude は 100万トークン級 |
| **システムプロンプト** | アプリ側が決める「役割・ルール」。ユーザーの入力とは別の欄で渡す |
| **max_tokens** | 出力の上限。超えると途中で切れる(`stop_reason: "max_tokens"`) |
| **ストリーミング** | 生成された分から少しずつ受け取る |
| **thinking(思考)** | 答える前にモデルが内部で考える機能。深さを effort で調整 |
| **ツール使用(Function Calling)** | モデルが「この関数をこの引数で呼んで」と頼み、アプリが実行して結果を返す |
| **構造化出力** | 決めた JSON スキーマどおりの形で答えさせる |
| **埋め込み(Embedding)** | 文章を意味の近さで比べられる数値の列(ベクトル)にしたもの。検索に使う |
| **RAG** | 質問に関係する文書を検索して、それを読ませてから答えさせる |
| **エージェント** | ツールを使いながら、何をするかをモデル自身が決めて進める仕組み |
| **ハルシネーション** | もっともらしい間違いを答えること |

## 得意・不得意
| 得意 | 不得意・注意 |
| --- | --- |
| 要約・言い換え・翻訳 | 最新の出来事(学習時点より後)を知らない |
| 分類・タグ付け・感情判定 | 正確な計算・大量の数値処理(ツールやコードに任せる) |
| 文章からの情報の抜き出し(→ JSON) | 根拠のない断言(ハルシネーション) |
| 下書き・アイデア出し・コード生成 | 毎回まったく同じ出力が必要な処理 |
| 自然な言葉での問い合わせ対応 | 誤りが許されない最終判断(人が確認する) |

## 複雑さの段階(公式の考え方)
「まずは一番シンプルな形で作る」が基本。
| 段階 | 形 | 例 |
| --- | --- | --- |
| 1. 単発の呼び出し | 1回送って1回受け取る | 要約、分類、抜き出し、Q&A |
| 2. ワークフロー | **コードが**手順を決め、途中で何度か LLM を呼ぶ | 「抜き出し → 検証 → 下書き → 校正」 |
| 3. エージェント | **モデルが**次に何をするか決め、ツールを繰り返し使う | 調べ物、コード修正、複数システムをまたぐ作業 |
- エージェントにするのは、手順を前もって決められない・結果に見合う価値がある・失敗を検出して戻せる、が揃うときだけ
- 段階が上がるほど**遅く・高く・予測しにくく**なる

## アプリの構成
```
[ブラウザ] ──(自分の API)──▶ [サーバー] ──▶ [LLM API]
                                  │
                                  ├─ 認証(誰が使っているか)
                                  ├─ 利用制限(1人あたりの回数・トークン)
                                  ├─ プロンプトの組み立て(システムプロンプト + 履歴 + 検索結果)
                                  ├─ ツールの実行(DB・外部 API)
                                  └─ ログ・計測(トークン数・遅延・エラー)
```
- **ブラウザから LLM の API を直接呼ばない**: API キーが見えてしまい、他人に使われて課金される
- サーバーは [[Hono]](Workers・Node.js)や [[Next.js]] の Route Handler が書きやすい → [[AIアプリ開発_06_画面との連携(AI SDK・Hono・Next.js)]]
- 会話履歴は API 側に残らない(状態を持たない)。続きを話すには、**アプリが DB に保存して毎回送る**

## どの会社のモデルを使うか
| 選び方 | 目安 |
| --- | --- |
| 品質 | 自分のタスクで**実際に試して評価する**のが一番確実 |
| 料金 | 入力・出力トークンの単価 × 量。キャッシュやバッチで大きく下がる |
| 速さ | 小さいモデルほど速い。体感はストリーミングで改善できる |
| 機能 | ツール使用・構造化出力・画像入力・PDF 入力・長いコンテキストなど |
| データの扱い | 学習に使われないか、保存期間、リージョン |
- 複数社を切り替えられるようにしたいなら Vercel AI SDK のような共通ライブラリを使う(→ 06)。Claude 固有の機能を深く使うなら公式 SDK
- OpenAI の料金の例 → [[OpenAI]]
