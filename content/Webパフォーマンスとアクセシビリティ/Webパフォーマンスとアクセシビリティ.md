## 押さえどころ
### パフォーマンス
- 指標は **Core Web Vitals**: **LCP ≤ 2.5秒**(表示)、**INP ≤ 200ms**(反応)、**CLS ≤ 0.1**(ずれ)
- 判定は**実際の利用者の75パーセンタイル**。手元の Lighthouse の点数だけでなく、本物の利用者のデータ(フィールドデータ)を見る
- 効くことが多い順: **画像**(サイズ・形式・優先度)、**JavaScript を減らす**、サーバーの応答(キャッシュ・CDN)、フォント
- 低速な端末・回線(スマホ・4G)で確かめる

### アクセシビリティ
- 目標は **WCAG 2.2 の レベル AA**
- 日本では**2024年4月から、民間事業者にも「合理的配慮」の提供が義務**になった(障害者差別解消法の改正)
- まず**正しい HTML の要素**を使う(`<button>`・`<a>`・`<label>`・見出し)。ARIA は最後の手段
- **キーボードだけで全部操作できる**か、**フォーカスが見える**か
- 文字と背景の**コントラスト 4.5:1 以上** → [[デザイントークン_05_運用(テーマ・アクセシビリティ・AI・チェックリスト)]]
- 自動チェックで見つかるのは一部。**キーボード操作とスクリーンリーダーで実際に触る**

## 2つは重なる
| 対策 | パフォーマンス | アクセシビリティ |
| --- | --- | --- |
| 正しい HTML で書く | JS が減る | 支援技術が理解できる |
| 画像に `width` / `height` と `alt` | レイアウトのずれ(CLS)を防ぐ | 画像の内容が伝わる |
| 低速な環境でも使える | 速い | 回線・端末に制約がある人も使える |
| アニメーションを控えめに | 描画が軽い | 動きで酔う人への配慮(`prefers-reduced-motion`) |
