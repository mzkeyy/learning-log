## ハーネスとは
**モデルの周りにある、エージェントを動かすための仕組み全部**。馬具(harness)が馬の力を目的の方向に伝えるように、モデルの能力を安全に・確実に仕事へつなげる。
```
エージェント = モデル + ハーネス

ハーネスの中身:
  ループ(考える → ツール → 結果 → また考える)
  ツールとその権限・サンドボックス
  コンテキストの管理(何を入れ、何を消すか、圧縮)
  状態の保存(進捗・メモ・git)
  検証(テスト・lint・型・評価役のエージェント)
  人の承認・介入のポイント
  ログ・トレース・コスト管理・再試行
```
- 2026年に広まった言葉。OpenAI がエージェントだけで製品を作った実験の記事(2026年2月)、Anthropic の長時間エージェントの記事、Martin Fowler のサイトの記事(Birgitta Böckeler、2026年4月)などで整理された
- **同じモデルでも、ハーネスで結果が大きく変わる**。Claude Code・Codex・Cursor の差の多くはハーネスの差

## 2つのハーネス
| | 製品に組み込まれたハーネス | **自分たちのハーネス** |
| --- | --- | --- |
| 何か | Claude Code・Codex などが最初から持つもの(システムプロンプト・ツール・ループ・圧縮) | チームが用意して変えられるもの |
| 例 | エージェントループ、ファイル操作のツール、権限の仕組み | CLAUDE.md / AGENTS.md、Skills、Hooks、MCP、テスト、lint、CI、サンドボックス、ドキュメント |
| 誰が直す | ツールの提供元 | **自分たち** |
- コーディングエージェントを**使う**側の仕事は、自分たちのハーネスを整えること → [[AIエンジニアリング_04_コーディングエージェントのハーネス(実践)]]
- 自分でエージェントを**作る**なら、ハーネス全部を設計する(Agent SDK・Managed Agents を土台にもできる)→ [[AIアプリ開発_05_エージェント(ループ・Agent SDK・Managed Agents)]]

## ガイドとセンサー(Martin Fowler のサイトの整理)
| | **ガイド**(先回りして導く) | **センサー**(結果を見て直させる) |
| --- | --- | --- |
| 役割 | 行動する**前に**、良い方向へ誘導する | 行動した**後に**観察し、エージェント自身が直せるようにする |
| **計算で行う**(確実・速い) | テンプレート、コード生成、型、スキーマ、ディレクトリ構成の決まり | **テスト、型チェック、lint、構造のテスト、ビルド、CI** |
| **推論で行う**(柔軟・確率的) | CLAUDE.md / AGENTS.md、Skills、設計ドキュメント、例 | **評価役の AI**、AI によるコードレビュー |
- **ガイドだけでは不十分**: 指示文は守られる確率が上がるだけで、保証にはならない
- **センサーがあると、エージェントが自分で失敗に気づいて直せる**(テストが落ちる → 読む → 直す)
- 計算で行えるもの(lint・テスト)は計算で。推論(AI の判断)は、計算できない品質(デザイン・読みやすさ・仕様との合致)に使う

## ハーネスの部品の設計
| 部品 | 設計のポイント |
| --- | --- |
| **ツール** | 少なく・目的別に。権限は最小。結果は簡潔に → [[AIアプリ開発_08_MCPサーバーを作る(TypeScript SDK・stdio・HTTP)]] |
| **サンドボックス** | ファイル・ネットワーク・秘密情報へのアクセスを制限。壊しても戻せる場所で動かす → [[05_権限とセキュリティ]] |
| **権限・承認** | 取り消せない操作(本番・削除・送信・支払い)は人の承認 |
| **状態と記録** | 進捗をファイルと git に。次のセッションが続きから始められる |
| **検証** | テスト・lint・型・E2E・評価役。**検証できないことは任せない** |
| **ループの制御** | 最大ターン数・予算・タイムアウト・止める条件 |
| **観測** | 何をしたか・なぜか・いくらかかったかを記録 → [[オブザーバビリティ]] |

## 生成と評価を分ける
- エージェントに**自分の成果物を評価させると甘くなる**(特にデザインなど主観の入るもの)
- **作る役と評価する役を分ける**: 評価役は実際に動かして(ブラウザを操作して)、基準に沿って採点し、基準を下回れば差し戻す
- 評価の基準を**具体的に書く**ことで、主観的な品質も採点できる形になる
- 評価役のコストに見合うのは、**今のモデルが1人では確実にできない難しさ**のタスク
→ 具体例は [[AIエンジニアリング_04_コーディングエージェントのハーネス(実践)]]

## ハーネスは育てて、削る
- ハーネスの部品は、それぞれ「**モデルが1人ではできないこと**」についての仮定を表している
- モデルが良くなると、その仮定は外れる(例: 以前のモデルで必要だった「コンテキストのリセット」が、新しいモデルでは不要になった)
- 新しいモデルが出たら:
  1. 評価で今のハーネスの性能を測る
  2. **部品を1つずつ外して**、性能が落ちるか確かめる(一気に外すと、どれが効いていたかわからない)
  3. 効いていない部品は外す。新しくできるようになったことに合わせて部品を足す
- 「モデルの弱点を補う工夫」をずっと残すと、かえって性能を下げることがある

## ハーネスを作るか、使うか
| やりたいこと | 選択 |
| --- | --- |
| コードを書かせる | Claude Code・Codex を使い、**自分たちのハーネス**(リポジトリ側)を整える |
| 自分の製品にエージェントを組み込む(コード・ファイル操作) | **Claude Agent SDK**(Claude Code のハーネスをライブラリとして) |
| 自作ツールだけのエージェント | Claude API + Tool Runner |
| 実行環境ごと任せたい・長時間・定期実行 | **Managed Agents** |
