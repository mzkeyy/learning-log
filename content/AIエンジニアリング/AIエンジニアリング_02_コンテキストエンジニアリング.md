## コンテキストエンジニアリングとは
**モデルが推論するときに見る情報(トークン)の全体を、選び・並べ・保つ**技術。プロンプト(指示文)だけでなく、システムプロンプト・ツールの定義・例・検索した資料・ツールの結果・会話の履歴・メモまで含む。
> 問いは「どんなコンテキストの構成なら、望む振る舞いを一番引き出せるか」(Anthropic)

## 前提: 注意は有限
- コンテキストウィンドウが 100万トークンあっても、**長くなるほど個々の情報への注意は薄まる**(context rot)
- 関係ない情報・古い情報・重複は、性能を下げるノイズになる
- 目標は「**できるだけ少なく、信号の強いトークン**」
- 長いほど費用と遅延も増える → [[AIアプリ開発_07_評価・コスト・セキュリティ・運用]]

## コンテキストの部品と設計
| 部品 | 設計のポイント |
| --- | --- |
| **システムプロンプト** | ちょうどいい高さで書く(下) |
| **ツールの定義** | 少なく・重ならず・説明が明確。人が「どれを使うか」迷うなら AI も迷う |
| **例**(few-shot) | 例外ルールを並べるより、**典型的で多様な例を少し** |
| **取ってきた資料** | 関係する部分だけ。出典付き → [[AIアプリ開発_04_RAG(埋め込み・ベクトル検索・引用)]] |
| **ツールの結果** | 大きすぎる結果は要約・件数制限。古い結果は消す |
| **会話の履歴** | 長くなったら圧縮・要約 |
| **メモ・記憶** | 会話の外(ファイル・DB)に置き、必要なときに読む |

### システムプロンプトの「高さ」
| 低すぎる(細かすぎる) | ちょうどいい | 高すぎる(あいまい) |
| --- | --- | --- |
| if-else のような細かい手順を全部書く。想定外の状況で壊れる | 目的・判断の基準・優先順位・制約を書く。具体的だが判断の余地を残す | 「いい感じに手伝って」。何を期待されているかわからない |
- **最小限から始めて、失敗を見て足す**。最初から全部の場合を書かない
- 「なぜそうしてほしいか」を書くと、書いていない状況でも正しく判断しやすい
- 最新のモデルは指示によく従うので、昔の「必ず」「絶対に」の連呼は逆効果になることがある

## 必要なときに取りに行く(Just-in-Time)
```
❌ 全部先に入れる: リポジトリの全ファイル・全ドキュメントをコンテキストへ
✅ 地図だけ渡し、必要な時に取りに行かせる:
   CLAUDE.md / AGENTS.md(どこに何があるか)+ grep・glob・read・検索ツール
```
- 軽い**参照**(ファイルパス・URL・クエリ)だけ持たせ、中身は必要なときにツールで読む
- 人間も全部を覚えずに、索引や検索を使うのと同じ
- 速さが要る部分は先に入れ、残りは探させる(組み合わせ)→ Claude Code はこの形 → [[02_仕組み(エージェントループ・ツール・コンテキスト)]]

## 長い作業でコンテキストを保つ
| 方法 | 内容 | 向く場面 |
| --- | --- | --- |
| **圧縮(compaction)** | 履歴を要約して置き換える | 会話・作業を続けたいとき。Claude API・Claude Code の機能 |
| **ツール結果の削除**(context editing) | 古いツールの結果を消す | 大量にファイルを読む・検索する作業 |
| **構造化したメモ** | 進捗・TODO・決定事項をファイルに書き、次に読む | 何時間・何日もかかる作業 |
| **リセット + 引き継ぎ** | 新しいセッションを始め、引き継ぎメモを読ませる | 圧縮では残る混乱をリセットしたいとき |
| **サブエージェント** | 調査を別のコンテキストで行い、要約(数千トークン)だけ受け取る | 広い調査・大量の読み込み → [[10_サブエージェント]] |

## 記憶(メモリ)
| 種類 | 例 |
| --- | --- |
| 指示・方針(毎回読む) | CLAUDE.md / AGENTS.md、システムプロンプト → [[04_CLAUDE.mdとメモリ]] / [[mdファイル使い分け]] |
| 作業の状態 | 進捗ファイル・TODO・計画・git の履歴 |
| 長期の知識 | ドキュメント・ADR・用語集 → [[アーキテクチャ設計_07_設計ドキュメントとADR]] |
| 会話をまたぐ記憶 | Claude API のメモリツール、Managed Agents のメモリ → [[AIアプリ開発_03_ツール使用と構造化出力]] |
- 記憶は**古くなる**。コードと合わなくなったドキュメントは、AI を間違った方向に導く → 定期的に見直す(→ 04)

## プロンプトキャッシュとの関係
- 並び順: **変わらないもの(システムプロンプト・ツール)を先に、変わるもの(質問・時刻)を後に**
- 途中のシステムプロンプトを書き換えるとキャッシュが効かなくなる。途中で指示を足すなら、会話の後ろに追加する
→ [[AIアプリ開発_07_評価・コスト・セキュリティ・運用]]

## チェックリスト
- [ ] システムプロンプトは目的・基準・制約が書かれ、細かすぎず・あいまいすぎない
- [ ] ツールは少なく、説明だけで使い分けがわかる
- [ ] 大きな資料は先に全部入れず、必要に応じて取りに行く形にした
- [ ] 長い作業には、圧縮・メモ・サブエージェントのどれかを用意した
- [ ] 外部から来た文章(資料・ツールの結果)は、データとして区切っている(プロンプトインジェクション対策)
- [ ] コンテキストを変えたら評価で比べている
