## LLMOps とは
AI 機能を本番で**安全に・安定して・お金を管理しながら**動かし続けるための運用。普通の運用(→ [[オブザーバビリティ]])に、AI 特有のもの(品質の揺れ・プロンプトインジェクション・コスト・モデルの更新)が加わる。

## ガードレール(安全の仕組み)
**入力・出力・行動**の3か所で守る。
| 場所 | チェックの例 | 方法 |
| --- | --- | --- |
| **入力** | 長すぎる入力、禁止の話題、個人情報、攻撃的な指示 | 長さ制限、ルールベースの判定、分類用の小さなモデル |
| **出力** | スキーマどおりか、禁止の内容、個人情報の漏れ、根拠のない断言 | 構造化出力、正規表現、分類器、出典のチェック |
| **行動**(ツール) | 権限外の操作、取り消せない操作 | **権限の最小化**、許可リスト、人の承認、サンドボックス |
- 一番大事なのは**行動のガードレール**。文章の問題より、AI が勝手に何かを**してしまう**問題のほうが被害が大きい
- **プロンプトインジェクションは完全には防げない**前提で、AI にできることを制限する
  - 外部の文章(Web・メール・資料・ツール結果)を読むエージェントに、**秘密情報への権限と外部への送信の権限を同時に持たせない**
  - 外部の文章はデータとして区切り、その中の指示に従わない設計
→ [[AIアプリ開発_07_評価・コスト・セキュリティ・運用]] / [[Webセキュリティ対策]]

## 監視
| 項目 | なぜ |
| --- | --- |
| エラー率(429・529・タイムアウト・`refusal`) | 障害・レート制限・断られた回数 |
| 遅延(最初の文字まで・全体) | 体感 |
| **トークン・費用**(ユーザー別・機能別) | 予算超過・悪用 |
| キャッシュの効き具合 | コスト |
| **品質の指標**(本番のサンプルの採点・👍👎) | 品質の変化にすぐ気づく |
| ツール呼び出しの回数・失敗・ループの長さ | エージェントの暴走 |
- 1つのリクエストで何が起きたか(プロンプト・ツール・結果)を**トレース**で追えるようにする。Claude の SDK・API は OpenTelemetry に対応 → [[オブザーバビリティ_04_トレースとOpenTelemetry]]
- 会話の本文を記録するかは、**個人情報と保存期間のルール**を決めてから

## コスト管理
- **ユーザーごと・機能ごとの上限**(1日のトークン・回数)
- プロンプトキャッシュ・バッチ・effort・モデルの選択で下げる → [[AIアプリ開発_07_評価・コスト・セキュリティ・運用]]
- エージェントには**予算**(最大ターン・トークン・金額)を必ず付ける
- 「1リクエストの値段」ではなく「**1つの仕事を終えるまでの値段**」で比べる
- 予算アラートを API の管理画面と社内の監視の両方に

## モデルが変わるとき
モデルは数か月ごとに新しくなり、古いものは提供終了になる。
| 手順 | 内容 |
| --- | --- |
| 1. 提供終了の予定を把握 | 使っているモデルの終了日をカレンダーに |
| 2. 評価セットで比べる | 新しいモデルで評価を回し、品質・コスト・遅延を比べる → [[AIエンジニアリング_05_評価(evals)の設計と運用]] |
| 3. API の違いを確認 | パラメータ・挙動の変更(例: 新しいモデルでは thinking の設定やサンプリングのパラメータが変わることがある) |
| 4. プロンプト・ハーネスを見直す | 古いモデル向けの工夫を外し、必要なら足す → [[AIエンジニアリング_03_ハーネスエンジニアリング(エージェント=モデル+ハーネス)]] |
| 5. 段階的に切り替え | 一部の利用者から。すぐ戻せるように(モデル名を設定で切り替えられるように) |
- モデル名はコードに散らばらせず、**設定で1か所**に
- 断られた・混雑したときの**代わりのモデル**(フォールバック)を用意する

## 人の関与(Human-in-the-loop)
| 場面 | 関わり方 |
| --- | --- |
| 取り消せない操作 | 実行前に承認 |
| 確信度が低い・規約に触れそう | 人に回す |
| 品質の確認 | サンプルを人が見る |
| 利用者 | 修正・取り消し・フィードバックができる UI |
- 「AI が提案、人が決定」から始め、評価で十分な品質が確認できた範囲だけ自動化を広げる

## 障害への備え
- AI の API が落ちたとき・遅いときの**劣化運転**(AI なしで使える機能、「混み合っています」の表示)→ [[アーキテクチャ設計_06_障害に強い設計(タイムアウト・リトライ・サーキットブレーカー)]]
- 長い処理はキューで非同期に → [[アーキテクチャ設計_04_非同期処理とイベント駆動(キュー・Pub-Sub・冪等性)]]
- 自動リトライの回数と、エージェントの最大ターンを制限(暴走でお金が溶けないように)

## 責任とルール
- AI の出力であることを利用者に示す、間違う可能性を伝える
- 利用規約・プライバシーポリシーに、AI の利用・データの扱い・保存期間を書く
- 使っている AI の提供元の利用ポリシーを守る
- 社内での AI 利用のルール(入れてよいデータ・使ってよいツール)を決める

## チェックリスト
- [ ] 入力・出力・行動のガードレールがある(特にツールの権限)
- [ ] トークン・費用・遅延・エラー・品質を監視している
- [ ] ユーザーごとの利用上限とエージェントの予算がある
- [ ] モデル名は設定で切り替えられ、提供終了の予定を把握している
- [ ] モデルを変えるときは評価で比べ、段階的に切り替える
- [ ] AI の API が使えないときの動きを決めている
- [ ] 取り消せない操作は人が承認する
- [ ] 本番の失敗を評価セットに足す流れがある
