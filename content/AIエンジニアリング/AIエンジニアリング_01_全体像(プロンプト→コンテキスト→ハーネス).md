## AI エンジニアリングとは
| | 機械学習エンジニアリング | **AI エンジニアリング** |
| --- | --- | --- |
| 中心 | モデルを**作る・学習させる** | 既存のモデル(API)を**使って**製品を作る |
| 主な作業 | データ収集・学習・チューニング | プロンプト・コンテキスト・ツール・ハーネス・評価・運用 |
| 必要な知識 | 統計・数学・GPU | ソフトウェア開発 + LLM の性質の理解 |
| 品質の測り方 | 学習データでの精度 | **評価(evals)**と本番のモニタリング |
- Web エンジニアがそのまま入りやすい領域。ソフトウェア設計・テスト・運用の知識が直接活きる
- 「AI を使って開発する」(Claude Code など)と「AI を組み込んだ製品を作る」の両方で同じ考え方が使える

## LLM の性質(設計の前提)
| 性質 | 設計への影響 |
| --- | --- |
| **確率的**(同じ入力でも出力が揺れる) | 完全一致のテストでなく評価で測る。重要な部分はコードで検証 |
| **見えているものしか知らない** | 必要な情報を渡す(コンテキスト)か、取りに行かせる(ツール) |
| **注意は有限**(長いと重要な情報を見落とす) | 渡す情報を絞る・整理する |
| **会話の外の記憶がない** | 記録をファイル・DB に残し、次に読ませる |
| **自分の出力に甘い** | 評価を別の仕組み(テスト・別のエージェント・人)に |
| **指示どおりに動く保証はない** | 大事なルールはコード(lint・権限・型・検証)で強制 |
| **モデルは更新される** | 前提を定期的に見直す。評価で比べる |

## 3つの層
```
┌─────────────── ハーネス ───────────────────┐
│ ループ・ツール・権限・サンドボックス・状態の保存 │
│ 検証(テスト・lint・評価役)・ログ・人の承認      │
│  ┌──────────── コンテキスト ─────────────┐   │
│  │ システムプロンプト・ツールの説明・例         │   │
│  │ 検索した資料・ツールの結果・会話の履歴       │   │
│  │  ┌──── プロンプト ────┐                 │   │
│  │  │ 今回の指示          │                 │   │
│  │  └──────────────────┘                 │   │
│  └─────────────────────────────────────┘   │
└──────────────────────────────────────────┘
```

## AI エンジニアの仕事
1. **タスクを分解する**: どこを AI に任せ、どこをコードでやるか(計算・検証・権限はコード)
2. **一番シンプルな形を選ぶ**: 1回の呼び出し → ワークフロー → エージェント → [[AIアプリ開発_01_全体像(LLMの仕組み・できること・構成)]]
3. **コンテキストとツールを設計する**
4. **ハーネスを作る**: 検証・制約・記録・人の関与
5. **評価で測る**: 変更のたびに同じ評価セットで比べる → [[AIエンジニアリング_05_評価(evals)の設計と運用]]
6. **運用する**: 監視・コスト・安全・モデル更新への対応 → [[AIエンジニアリング_06_本番運用(ガードレール・監視・モデル更新)]]

## よくある落とし穴
| 落とし穴 | 対策 |
| --- | --- |
| プロンプトを感覚で直し続ける | 評価セットを作り、数字で比べる |
| 全部をエージェントにする | 決まった手順はコード・ワークフローで |
| 何でもコンテキストに詰め込む | 必要なときに取りに行かせる(ツール・検索) |
| 指示文でルールを守らせようとする | lint・テスト・権限・型で機械的に強制 |
| 古いモデル向けの工夫をずっと残す | モデルが変わったら、部品を1つずつ外して効果を確かめる |
| デモでうまくいった = 完成 | 本番のデータ・ずれた入力・失敗時で確かめる |
