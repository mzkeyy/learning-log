**複数のアプリやパッケージ(フロント・API・共通の型や部品)を、1つのリポジトリでまとめて管理する方法**。共通のコードを公開せずに共有でき、変更を1つの PR でまとめて行える。道具は pnpm workspace(パッケージ管理)+ Turborepo(タスク実行とキャッシュ)+ Biome / ESLint(コードの品質)が定番。

pnpm・Turborepo・Biome の公式ドキュメント(**2026年10月時点。pnpm 12、Turborepo 2.11、Biome 2.6、TypeScript 7**)を読んで整理したノート群の入口。

## 典型的な構成
```
my-product/
├── apps/
│   ├── web/          # Next.js / React(画面)
│   ├── api/          # Hono(API)
│   └── docs/
├── packages/
│   ├── ui/           # 共通の部品(shadcn/ui ベースなど)
│   ├── db/           # Drizzle のスキーマ・クライアント
│   ├── shared/       # 型・Zod スキーマ・ユーティリティ
│   └── config/       # tsconfig・lint の共有設定
├── pnpm-workspace.yaml
├── turbo.json
├── biome.json
└── package.json
```

## 押さえどころ(2026年10月時点)
- パッケージ管理は **pnpm**(速い・ディスクを節約・依存の取り違えが起きにくい)。workspace と catalog で依存のバージョンを揃える
- 内部パッケージは `"@acme/ui": "workspace:*"` で参照
- タスク(build・test・lint)は **Turborepo** で依存順に並列実行し、**結果をキャッシュ**(変更がなければ一瞬)
- lint と format は **Biome**(1つの道具で速い)。細かい ESLint のプラグインが必要なら ESLint を併用
- tsconfig・lint の設定は**共有パッケージ**にまとめる
- [[Hono]] の RPC で API の型をフロントと共有するときに特に便利(**Hono のバージョンを揃える**)
- 供給網攻撃への備え: pnpm は**依存パッケージのインストール時スクリプトを既定で実行しない**、公開直後のバージョンを入れない設定も既定 → [[モノレポ_02_pnpm workspace(workspace・catalog・filter)]]
