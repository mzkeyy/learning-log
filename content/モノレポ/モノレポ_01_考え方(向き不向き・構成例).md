## モノレポとポリレポ
| | モノレポ(1つのリポジトリ) | ポリレポ(リポジトリを分ける) |
| --- | --- | --- |
| 共通コードの共有 | **フォルダを参照するだけ** | npm に公開してバージョンを上げる |
| 複数にまたがる変更 | **1つの PR** | 複数の PR を順番に |
| 依存のバージョン | 揃えやすい | ばらばらになりがち |
| CI | 工夫しないと遅い(全部を毎回) | リポジトリごとに軽い |
| 権限 | 細かく分けにくい | リポジトリ単位で分けられる |
| 向く場面 | **1つのプロダクトのフロント・API・共通部品** | 独立したチーム・別々のリリース・外部公開のライブラリ |
- 「全社のコードを全部1つに」(Google 型)である必要はない。**一緒に変わるものを1つにまとめる**のが目安

## 何がうれしいか
- API の型・Zod のスキーマ・定数をフロントとサーバーで**共有**できる(二重定義が消える)
- 共通の UI 部品を複数のアプリで使える → [[デザインシステム]]
- 「API の項目を変える → フロントを直す」を**1つの PR・1回のレビュー**で
- 設定(tsconfig・lint・format)を1か所で管理
- AI のコーディングエージェントも、**関係するコードを全部見られる**ので変更の影響を把握しやすい

## 注意点
- 何もしないと CI で全部をビルド・テストして遅くなる → 変更されたものだけ(Turborepo → [[モノレポ_03_Turborepo(タスク・キャッシュ・CI)]])
- パッケージの境界があいまいになり、何でも何でも参照する「スパゲッティ」になりやすい → 依存の方向のルールを決める
- リポジトリが大きくなると git やエディタが重くなる
- デプロイはアプリごとに設定する(Vercel・Cloudflare などはモノレポのサブフォルダを指定できる)

## 構成の決め方
```
apps/      … デプロイする単位(画面・API・バッチ)
packages/  … apps から使われる部品(デプロイしない)
```
| パッケージ | 中身 | 使う側 |
| --- | --- | --- |
| `@acme/shared` | 型、Zod スキーマ、定数、純粋な関数 | web・api どちらも |
| `@acme/ui` | React の部品 | web |
| `@acme/db` | Drizzle のスキーマ・クライアント → [[PostgreSQLとDrizzle]] | api・バッチ |
| `@acme/config` | tsconfig・Biome / ESLint の共有設定 | 全部 |

### 依存の方向
```
apps/web ─┐
          ├─▶ packages/ui ─▶ packages/shared
apps/api ─┴─▶ packages/db  ─▶ packages/shared
```
- **apps は packages に依存してよいが、逆はダメ**。packages 同士も一方向に
- `packages/shared` にサーバー専用のコード(DB・秘密情報)を入れない(ブラウザ向けのバンドルに混ざる)
- 依存のルールを道具でチェックすることもできる(Turborepo の boundaries、ESLint のルールなど)

## 内部パッケージの作り方(2通り)
| 方式 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **ソースのまま参照**(Just-in-Time) | `package.json` の `exports` で `.ts` を直接指す。使う側のビルドツールが変換 | ビルド不要・設定が簡単 | 使う側が TS を変換できる必要がある |
| ビルドして参照 | `tsc` などで `dist/` に出力して参照 | 使う側を選ばない、キャッシュが効く | ビルドの手間 |
```jsonc
// packages/shared/package.json(ソースのまま参照する例)
{
  "name": "@acme/shared",
  "private": true,
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./schemas": "./src/schemas.ts"
  }
}
```
- アプリの内部だけで使うなら、まずは**ソースのまま参照**で始めるのが簡単(Vite・Next.js・Wrangler は TS を変換できる)

## 道具の選択肢
| 役割 | 定番 | 他の選択肢 |
| --- | --- | --- |
| パッケージ管理・workspace | **pnpm** | npm / Yarn / Bun の workspaces |
| タスク実行・キャッシュ | **Turborepo** | Nx(高機能・大規模向け)、pnpm 自体のタスク実行 |
| lint / format | **Biome** | ESLint + Prettier |
| 型チェック | TypeScript(7 は Go 製で高速) | |
| バージョン・公開 | Changesets | |
