## 全体像(典型的な Web サービス)
```
利用者 ─▶ CDN ─▶ ロードバランサー / API Gateway
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
     BFF(画面用 API)    外部向け API
          │                   │
          ▼                   ▼
   ┌── アプリ(モノリス or 複数のサービス)──┐
   │                                          │
   ▼            ▼              ▼              ▼
  DB       キャッシュ       キュー       ストレージ
(主 + 読み取り用)(Redis 等)  (SQS 等)    (S3 等)
                               │
                               ▼
                         ワーカー(非同期処理)
```

## 押さえどころ
- アーキテクチャは**トレードオフの選択**。「一番良い構成」はなく、要件(規模・チーム・速さ・費用)に合うものを選ぶ
- **最初はモノリス**(できればモジュールを分けたモジュラーモノリス)から。マイクロサービスは、チームと規模が必要になってから
- 画面のための API は **BFF** で整える。外部公開の API は REST + OpenAPI が無難
- 時間のかかる処理・他のサービスへの通知は**キューで非同期**に。処理は**冪等**に
- 遅いときは**計測してから**キャッシュ・スケール
- 他のサービスは**必ず失敗する**前提で、タイムアウト・リトライ・劣化運転を設計する
- 決めたことは**理由と一緒に記録**(ADR)
